@why 과거 후기에 반복해서 나온 기본 질문입니다. 2지망이 양산기술(전공정 팹)이라 더 중요합니다. 순서와 각 공정의 목적을 한 문장씩.
@p 웨이퍼 제조 → 산화 → 포토 → 식각 → 증착·이온 주입 → 금속 배선 → EDS → 패키징
@p 포토·식각·증착이 층마다 반복된다는 점
@p 본인이 지원한 패키징의 위치
@m 순서대로 말씀드리겠습니다.

**웨이퍼 제조**는 실리콘 잉곳을 얇게 잘라 기판을 만드는 단계입니다. **산화**는 표면에 절연막인 산화막을 키웁니다. **포토**는 감광액을 바르고 마스크의 회로 패턴을 빛으로 옮깁니다. **식각**은 패턴대로 필요 없는 부분을 깎아 냅니다. **증착과 이온 주입**은 얇은 막을 입히고, 불순물을 넣어 전기적 특성을 만듭니다. **금속 배선**은 소자들을 금속으로 연결합니다. **EDS**는 웨이퍼 상태에서 칩의 전기적 특성을 검사해 양품과 불량을 가립니다. 마지막 **패키징**은 칩을 잘라 외부와 연결하고 보호합니다.

실제로는 포토, 식각, 증착이 **층마다 수십 번 반복**되고, 그 사이에 세정과 평탄화, 계측이 들어갑니다. 제가 지원한 직무는 이 가운데 마지막 단계인 **패키징**이고, HBM에서는 이 단계가 성능을 좌우한다고 이해하고 있습니다.

@k 패턴 :: 포토|노광|식각
@k 막·불순물 :: 증착|이온 주입
@k 배선·검사 :: 배선|EDS|검사
@k 패키징 :: 패키징|패키지
@k 반복 :: 반복|층마다|세정|평탄화

@q CVD와 ALD의 차이를 설명해 보세요.
@why 과거 후기에 나온 질문입니다. 화학 전공자에게 유리한 질문이니 반응 메커니즘으로 설명하세요.
@p CVD: 기체가 동시에 반응해 막 형성, 빠름
@p ALD: 원료를 번갈아 넣는 자기 제한 반응, 원자층 단위
@p 장단점과 쓰임
@m 둘 다 기체 원료의 화학 반응으로 막을 만드는 공정입니다.

**CVD**는 원료 기체들을 **함께 넣어** 표면과 그 근처에서 반응시켜 막을 쌓습니다. **속도가 빠르지만** 깊고 좁은 구조에서는 입구와 바닥의 두께가 달라지기 쉽습니다.

**ALD**는 원료를 **한 종류씩 번갈아** 넣습니다. 첫 번째 원료가 표면에 한 층만 붙으면 더 붙지 않는 **자기 제한 반응**을 이용하기 때문에, 한 사이클에 **원자층 한 층씩** 쌓입니다. 그래서 **두께 제어가 정밀하고**, 깊은 구멍 안쪽까지 **고르게 덮습니다**. 대신 속도가 느립니다.

그래서 미세하고 깊은 구조의 얇은 막에는 ALD를, 두껍고 빠르게 쌓아야 하는 막에는 CVD를 쓴다고 이해하고 있습니다.
@k CVD :: CVD|함께|동시에|빠르
@k ALD :: ALD|번갈아|한 층|원자층
@k 자기 제한 :: 자기 제한|self|더 붙지
@k 피복성 :: 고르게|단차|덮|균일
@k 쓰임 :: 얇은 막|깊은|두껍
@f TSV 공정에서 이런 증착이 쓰이는 곳은 어디입니까? || 구멍 안쪽 벽의 절연막. 칼럼에서는 CVD로 절연막을 입힌다고 설명.

@q 새로 들여온 장비에서만 수율이 낮게 나옵니다. 무엇을 어떤 순서로 점검하겠습니까?
@why 양산기술 면접 후기에 나온 상황형 질문입니다. 문제해결 PT의 소재로도 유력합니다. 정답보다 순서와 근거가 평가됩니다.
@p 먼저 "정말 장비 차이인가"부터 확인
@p 기존 장비와의 차이를 좁힘
@p 하드웨어 → 조건 → 자재·환경 순
@p 조치와 재발 방지 (셋업 기준)
@m 네 단계로 점검하겠습니다.

첫째 **현상 확인**입니다. 정말 그 장비 때문인지부터 봅니다. 같은 로트를 기존 장비와 나눠 진행한 데이터가 있는지, 불량이 **웨이퍼의 특정 위치나 특정 시간대**에 몰리는지를 확인합니다.

둘째 **기존 장비와의 차이 좁히기**입니다. 같은 조건값을 넣어도 실제 온도, 압력, 유량이 같은지 **장비 센서 데이터**를 기존 장비와 비교합니다.

셋째 **원인 후보 점검**입니다. 설치 상태와 부품, 센서 보정 같은 **하드웨어**, 조건값이 제대로 옮겨졌는지와 장비 간 보정 같은 **공정 조건**, 그리고 **자재와 환경** 순서로 봅니다.

넷째 **조치와 재발 방지**입니다. 원인을 고친 뒤 기존 장비와 결과가 맞는지 확인하고, 이번에 놓친 항목을 **셋업 점검 기준에 추가**합니다.

원인이 확인될 때까지는 해당 장비의 투입을 제한해서 **불량 확산을 먼저 막겠습니다**.
@k 현상 확인 :: 정말|로트|위치|시간대|확인
@k 차이 비교 :: 기존 장비|비교|센서|데이터
@k 하드웨어 :: 하드웨어|부품|설치|보정
@k 조건 :: 조건|레시피|조건값
@k 재발 방지 :: 재발|셋업|기준|추가
@k 확산 방지 :: 투입|제한|확산
@f 생산 일정이 급해서 그 장비를 세울 수 없다고 합니다. 어떻게 하겠습니까? || 위험을 숫자로 보고(불량 예상량 vs 생산 손실), 위험이 낮은 제품만 투입하는 등 대안 제시. 결정은 근거와 함께 상위에 요청.
@f 장비 제조사와 의견이 다르면 어떻게 하겠습니까? || 데이터로 대화. 뉴스룸에서도 장비사·현장과의 소통을 강조.

@q 수율이란 무엇이고, 수율을 높이려면 무엇을 관리해야 합니까?
@why 양산기술의 존재 이유입니다. 정의 → 떨어뜨리는 원인 → 관리 방법의 순서로.
@p 정의: 투입 대비 양품 비율, 단계별 수율
@p 원인: 결함(파티클), 공정 산포, 설비 차이
@p 관리: 결함 저감, 산포 관리, 조기 감지
@p 본인 경험
@m 수율은 **투입한 수량 대비 양품의 비율**입니다. 웨이퍼 가공, 웨이퍼 검사, 패키지, 최종 검사 단계마다 수율이 있고, 전체 수율은 이들의 곱이라서 **한 단계의 손실이 전체에 그대로 반영**됩니다.

수율을 떨어뜨리는 것은 크게 세 가지입니다. 파티클 같은 **결함**, 두께나 선폭이 목표에서 벗어나는 **공정 산포**, 그리고 **설비 간 차이**입니다.

그래서 관리도 세 방향입니다. 결함의 발생원을 찾아 줄이고, 공정 조건의 **여유를 넓히고 산포를 줄이며**, 이상을 **빨리 감지**해서 불량이 퍼지기 전에 막습니다.

저는 파일럿 라인에서 **불량을 유형별로 나눠 큰 것부터 줄이는 방식**으로 초기 수율을 올린 경험이 있어서, 이 접근을 그대로 적용할 수 있다고 생각합니다.
@k 정의 :: 양품|비율|투입
@k 단계 :: 단계|곱|전체
@k 원인 :: 결함|파티클|산포|설비
@k 관리 :: 여유|감지|줄이
@k 경험 :: 파일럿|유형|초기 수율
@f HBM처럼 여러 장을 쌓는 제품의 수율은 왜 더 어렵습니까? || 접합 한 번의 수율이 99%라도 여러 번 곱해지면 크게 떨어진다. 그래서 양품 칩만 쌓고, 접합 수율을 극단적으로 높여야 한다.

@q SPC와 공정능력지수(Cpk)를 설명해 보세요.
@why 뉴스룸에서 양산기술의 가장 중요한 역량으로 데이터 분석력을 꼽았습니다. 통계적 공정 관리의 기본 개념은 알고 가야 합니다.
@p SPC: 관리도로 이상을 조기 감지
@p 관리 한계 vs 규격 한계
@p Cpk: 규격 대비 산포와 치우침
@p 실제 사용 경험 (있다면)
@m **SPC**는 통계적 공정 관리입니다. 공정의 측정값을 시간 순서대로 **관리도**에 찍어서, 평소의 흔들림을 벗어나는 **이상 신호를 빨리 찾아내는** 방법입니다. 점이 관리 한계를 벗어나는 경우뿐 아니라, 한계 안이라도 **한쪽으로 계속 치우치거나 연속으로 오르내리는 경향**이 보이면 원인을 찾습니다.

여기서 **관리 한계**는 공정 데이터 자체에서 계산한 값이고, **규격 한계**는 제품이 만족해야 하는 값이라서 서로 다릅니다.

**Cpk**는 공정이 규격을 얼마나 여유 있게 만족하는지를 나타내는 지수입니다. 규격 폭에 비해 **산포가 작을수록, 평균이 규격 중심에 가까울수록** 커집니다. 산포만 보는 Cp와 달리 **평균의 치우침까지 반영**합니다.

[직접 채울 것: 현 직장에서 관리도나 공정능력지수를 실제로 써 본 경험이 있으면 한 문장]
@k SPC :: SPC|통계적|관리도
@k 이상 감지 :: 이상|벗어|경향|연속
@k 한계 구분 :: 관리 한계|규격
@k Cpk :: Cpk|공정능력|여유
@k 산포·치우침 :: 산포|평균|치우침|중심

@q 생산 일정이 급한데 설비에서 이상 징후가 보입니다. 라인을 세우겠습니까?
@why 뉴스룸에서 현직자가 "생산 일정에 영향을 주는 이슈의 우선순위를 정하는 것이 가장 어렵다"고 했습니다. 혼자 결정하는지, 근거를 만들어 보고하는지를 봅니다.
@p 즉답하지 않고 판단 기준을 먼저
@p 위험 크기 확인 (데이터)
@p 확산 방지 조치 + 보고
@p 품질 우선 원칙
@m 바로 세운다, 안 세운다를 정하기 전에 **위험의 크기를 먼저 확인**하겠습니다.

이상 징후가 **제품 품질에 영향을 주는 변수**인지, 지금까지 진행된 물량의 측정값에 변화가 있는지를 데이터로 봅니다. 그리고 계속 돌렸을 때 예상되는 **불량 규모**와 세웠을 때의 **생산 손실**을 비교할 수 있게 정리합니다.

품질에 영향을 줄 가능성이 확인되면, 해당 설비의 투입을 먼저 멈추고 **이미 진행된 물량을 구분해 두는 조치**를 한 뒤, 정리한 근거와 함께 **바로 보고**하겠습니다. 판단이 어려운 경우에도 혼자 끌어안지 않고 근거를 공유하겠습니다.

일정은 다시 맞출 수 있지만 **고객에게 나간 불량은 되돌릴 수 없다**고 생각합니다. 그래서 확신이 없을 때는 품질 쪽으로 판단하겠습니다.

@p 개발 환경과 양산 환경의 차이: 설비, 물량, 자재 편차
@p 함께 검증

@m 먼저 **누구의 잘못인지가 아니라 무엇이 다른지**를 찾겠습니다.

개발과 양산은 조건값이 같아도 환경이 다릅니다. **설비가 다르고**, 한두 장이 아니라 **대량으로 연속 진행**하며, **자재의 로트 간 편차**도 커집니다. 그래서 개발 때의 설비·자재·진행 수량과 양산의 조건을 나란히 놓고 차이를 좁히겠습니다.

그다음 개발 담당자와 **같은 데이터를 보면서** 어느 변수에 민감한지 확인하고, 조건의 **여유 폭**을 다시 잡겠습니다.

저는 개발 직무에서 파일럿 라인을 함께 경험했기 때문에, **개발 조건이 좁은 범위에서만 맞았을 가능성**을 먼저 의심하는 편입니다. 반대로 제가 개발 쪽에 있다면, 조건을 넘기기 전에 **변수를 일부러 흔들어 본 결과**까지 함께 넘기겠습니다.

@p DOE의 뜻과 왜 쓰는가
@p '타겟'의 의미: 가설로 변수를 좁힘
@p 실제 설계 ← 준비 필요 (인자, 수준, 반응값)
@p 상호작용
@m DOE, 즉 실험 계획법은 **여러 변수를 한 번에 체계적으로 바꿔서** 적은 실험으로 변수의 영향과 **변수 간 상호작용**을 알아내는 방법입니다. 한 번에 하나씩 바꾸는 방식보다 실험 수가 줄고, 변수들이 함께 작용할 때의 효과도 볼 수 있습니다.

제가 '타겟 DOE'라고 쓴 것은, 모든 변수를 다 넣지 않고 **메커니즘 가설로 중요한 변수를 먼저 좁힌 뒤** 실험했다는 뜻입니다.
