@p 조치: 다단 압축 / 결과
@m **상황**은 신규 소재 적용과 극판 폭 축소를 함께 진행하던 중, 같은 가압 조건인데 Curl이 크게 늘어난 것이었습니다. 가압력만 조절해서는 **연신율과 합제 밀도**를 동시에 맞출 수 없었습니다.

저는 먼저 **문제를 제가 정의**했습니다. '수직 압력이 어떤 경로로 길이 방향 연신으로 바뀌는가'로 질문을 좁힌 뒤, AI에 입자 경도, 바인더 탄성계수, 기재 두께 같은 조건과 폭 축소 상황을 주고 **가능한 메커니즘을 여러 개 제시하게** 했습니다.

그중 **'폭이 줄면 폭 방향으로 분산되던 변형이 길이 방향으로 몰린다'**는 가설과 **'경도가 높은 입자는 부서지지 않고 밀어내는 힘으로 작용한다'**는 가설을 골라, [직접 채울 것: 실제 데이터나 실험으로 검증한 방법]으로 확인했습니다.

@k 문제 정의 :: 정의|질문|좁힌|경로

@k 표현 인정 :: 오해|표현

@q AI의 답이 틀렸던 적이 있습니까? AI의 답을 어떻게 검증합니까?
@why 새 면접에서 AI 문항으로 가장 유력한 질문입니다. AI를 맹신하지 않는지, 자기만의 검증 절차가 있는지를 봅니다.
@p 틀렸던 실제 사례 하나
@p 검증 3단계: 이론 → 1차 자료 → 데이터·실험
@p 원칙 한 줄
@m 있습니다. [직접 채울 것: 실제 사례 한 가지 — 예: 그럴듯하지만 우리 조건과 맞지 않는 메커니즘을 제시한 경우]. 생성형 AI는 **그럴듯한 설명을 만들어 내기 때문에** 검증 없이 믿지 않습니다.

저는 세 단계로 확인합니다. 첫째, **물리 법칙과 단위**에 맞는지 제가 아는 이론으로 따져 봅니다. 둘째, 근거를 요구해서 **교과서나 논문 같은 1차 자료**와 대조합니다. 셋째, 가장 중요한 단계로 **현장 데이터나 작은 실험**으로 확인합니다. 가설이 맞다면 어떤 결과가 나와야 하는지를 먼저 적고, 실제 결과와 비교합니다.

AI의 답은 **가설 후보**이고, **결론은 데이터가 정한다**는 원칙으로 씁니다.
@k 사례 :: 틀린|틀렸|맞지 않|오류
@k 이론 확인 :: 물리|단위|이론
@k 자료 대조 :: 논문|교과서|1차|근거
@k 실험 확인 :: 데이터|실험|비교
@k 원칙 :: 가설|후보|결론
@f 검증할 시간이 없을 만큼 급한 상황이라면 어떻게 하겠습니까? || 검증 안 된 내용은 '미검증 가설'이라고 표시해서 공유. 조건 변경은 하지 않는다.

@why 지원서의 AI 경험이 '대화·토론'형이라 나올 수 있는 반박입니다. 방어만 하지 말고 한계를 인정해야 합니다.
@p 형식은 대화였지만 한 일은 세 가지
@p 결과가 공정 변경으로 이어졌다는 점
@p 한계 인정 + 넓힐 방향
@m 형식은 대화였지만, **검색하듯 답을 받아 쓴 것은 아닙니다**. 제가 한 일은 세 가지입니다. 문제를 **제가 먼저 정의**했고, AI에게 **서로 다른 가설을 여러 개 내게 한 뒤** 조건을 바꿔 가며 반박했고, 남은 가설을 **실험 계획으로 바꿔 검증**했습니다. 그 결과가 **다단 압축이라는 공정 변경**으로 이어졌습니다.

다만 한계도 인정합니다. **데이터 분석 자동화나 모델링**처럼 AI를 도구로 구현해 본 경험은 부족합니다. [직접 채울 것: 데이터 분석에 AI나 코드를 써 본 경험이 있다면 추가] 입사 후에는 공정 데이터 분석에 AI를 적용하는 쪽으로 넓혀 가겠습니다.
@k 차별점 :: 정의|가설|반박|검증
@k 결과 :: 다단|공정 변경|실험
@k 한계 :: 한계|부족|인정
@k 확장 :: 데이터 분석|넓혀|적용
@f 그러면 코딩이나 데이터 분석 도구는 어느 정도 다룹니까? || 사실대로. 컴퓨터활용능력 1급(엑셀)은 지원서에 있음. 그 외는 실제 수준만.

@why 채용 설명회에서 LLM 활용 능숙도가 아니라 "과제를 어떻게 정의하고 해결하는지"를 본다고 했습니다. 문제해결 PT의 평가 포인트와 같습니다.
@p 현상 / 바뀐 것 / 제약 세 가지를 먼저 적는다
@p Curl 사례에 대입
@p 문제 정의가 질문을 바꾼다
@m 세 가지를 먼저 적습니다. **현상**을 숫자와 조건으로 적고, **바뀐 것**을 적고, 동시에 만족해야 하는 **제약**을 적습니다.

Curl 문제에서는 '신규 소재 적용과 폭 축소 이후, 같은 가압 조건에서 Curl 증가, 단 합제 밀도는 유지해야 함'이 문제 정의였습니다.

이렇게 적고 나면 AI에게 던질 질문이 '왜 Curl이 생기나요'가 아니라 **'이 조건 변화가 변형 에너지의 방향을 어떻게 바꾸는가'**로 구체화됩니다. **문제 정의가 흐리면 AI의 답도 일반론에 그친다**는 것을 경험으로 배웠습니다.

@k 변화점 :: 바뀐|변화|변경
@k 제약 :: 제약|동시에|유지
@k 사례 :: curl|컬|폭|밀도
@k 교훈 :: 일반론|구체화|문제 정의
@f 문제 정의가 틀렸다는 것은 어떻게 알아챕니까? || 검증 결과가 가설과 계속 어긋날 때 → 정의 단계로 돌아간다.

@m 먼저 **AI 없이 제 생각을 적겠습니다**. 문제를 한 문장으로 정의하고, 제가 아는 범위에서 원인 가설과 우선순위를 씁니다.

그다음 AI에게는 **제가 놓친 가설이 있는지, 제 논리의 약점이 무엇인지**를 묻겠습니다. 받은 답은 과제에 주어진 자료와 맞는지 확인하고, **제가 근거를 설명할 수 있는 것만** 남기겠습니다.

마지막으로 **결론, 근거, 검증 계획, 리스크** 순서로 정리하겠습니다. 채용 설명회에서도 LLM을 얼마나 능숙하게 쓰는지가 아니라 **과제를 어떻게 정의하고 해결하는지**를 본다고 한 것으로 알고 있어서, 제 판단이 드러나게 쓰는 데 집중하겠습니다.
